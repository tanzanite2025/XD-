### ❓ 常见问题答疑与排查 (FAQ)

#### Q1：为什么之前无论执行多少次 `npm run build`，根目录的 `.exe` 时间都不会更新？
- **原因 1（命令职责分离）**：原项目默认的 `npm run build` 仅是前端打包命令（生成 `dist/` 静态网页），并不会自动调用 Rust 编译器重新生成桌面程序 `.exe`。现在我们已经通过全自动脚本将全流程打通，执行 `npm run build` 或双击 `一键打包发布.bat` 会同时打包前端与后端，自动刷新根目录 `.exe`！
- **原因 2（Windows 文件占用锁）**：如果后台有任何旧的 `计件管理系统.exe` 正在运行，Windows 会对正在执行的文件施加内核级独占锁（File-Lock），此时任何复制或重命名操作都会被系统拒绝（报 `Access is denied` 错误），导致修改时间永远卡死在之前的时刻。现在的全自动打包脚本会在编译前自动检查并优雅释放被占用的旧实例，确保每次构建 100% 刷新时间戳！

#### Q2：为什么根目录的文件名之前会显示为 `璁′欢绠＄悊绯荤粺.exe` 或 `璁'欢缁 $ 尪绯荤牌.exe` 乱码？
- **原因**：Windows 早期控制台与老版命令行默认使用 ANSI/GBK 字符集，而现代前端与 Git 采用标准的 UTF-8 编码。“计件管理系统”这 6 个汉字在 UTF-8 下由 18 个字节表示，当被 Windows 的 GBK 字符集错误地按每 2 字节强行解释时，就会拼凑出这些稀奇古怪的生僻字乱码。
- **解决方式**：目前全线重构了文件复制与发布脚本，全面通过 Node.js 原生 Unicode 标准库发布文件，根目录只保留纯正标准的 **`计件管理系统.exe`**，杜绝任何乱码。

## ⚙️ 核心特色：产品型号工位工艺路线体系 (MES Routing)

系统为满足碳纤维工厂**“不同产品型号在不同工位使用专属工艺程序与独立工价”**的工业化需求，全新实现了 MES 工位工艺路线联动体系：
1. **产品工艺路线配置**：
   - 进入【产品型号管理】模块，每款产品的操作列均提供【路线】入口；
   - 点击可唤起可视化路线弹窗，自由为该产品追加工序流转节点（如 `工序#1: 模具铺叠成型站 -> 铺叠程序01 (¥12.50)`，`工序#2: 数控钻孔成型站 -> 24孔专用程序 (¥6.80)`）；
   - 支持上移、下移、删除工步，保存后在产品列表中以 **Chips 箭头链路**直观呈现。
2. **极速记工台三级智能联动**：
   - 在【车间流水记工台】选择【加工产品型号】后，工位下拉框会自动收敛为该产品专属的工艺工位；
   - 选定工位后，系统自动锁定该工序的专用工艺程序并自动填入单价快照，彻底杜绝车间工人因误选工价或程序导致的核算偏差！
   - 支持切换为“-- 跨型号通用作业 / 无关联 --”模式，无缝兼容通用零星报工。

## 🎯 核心业务架构与工业规范

### 1. 自行车碳纤维轮圈标准孔数与主数据驱动
- **产品型号管理主数据**：统筹管理全厂所有碳纤维轮圈型号规格，编号全自动化生成，禁止手动输入冲突。
- **碳纤维轮圈标准内置孔数**：严格限定为 **`16, 18, 20, 21, 24, 28, 32, 36`** 八种行业标准规格，其他非标孔数彻底移除。
- **全系统输入强防呆**：工艺库与记工节点 100% 从主数据中心下拉单选读取型号与对应孔数规格，彻底终结手输造成的统计核算灾难。
- **工艺防误删保护**：当型号已被下游工序使用时，系统依据 Fail Loudly 原则阻止物理删除并阻断告警。

### 2. 部门-车间-工位三级树形管理 & 独立从属班组
- **三级组织树形结构**：支持动态录入与维护【部门】➔【车间】➔【工位】三级层级。
- **班组实体独立解耦**：班组为独立的从属数据，不嵌入三级树形。员工可归属于特定工位，同时也可独立加入班组。
- **记工台双核算支持**：记工时既可选择班组进行团队批量核算（自动按班组成员均摊/生成对应工票），也可直接单选人员进行个人独立核算。

### 3. 数据安全与保险箱 (备份与还原中枢)
1. **一键物理快照生成**：毫秒级复制并锁定一份完整的 `data/backups/piecework_backup_YYYYMMDD_HHMMSS.db` 副本。
2. **直达 Windows 资源管理器**：一键唤起原生 Explorer 定位到备份文件夹，支持 U 盘或异地冷存。
3. **安全前置物理还原 (Restore)**：在执行任何还原覆盖前，系统**强制自动创建当前状态的救援快照**（`pre_restore_safety_...db`），绝不会因为手误还原而丢失当天生产数据！

### 4. 多维专项 Excel 报表导出体系 (双击即开·永不乱码)
所有导出的 CSV 文件开头均内置 UTF-8 BOM 标头 (`\u{FEFF}`)，在任何版本 Windows 系统的 Microsoft Office Excel 下双击打开 100% 正常显示中文：
1. **【生产流水明细总账】导出**：包含工单批次、工段工位、员工工号/姓名、班组、工艺代码/名称、产品型号与孔数、合格/废品数、单价快照、核算状态。
2. **【员工计件工资总账】导出**：包含员工工号、姓名、所属班组、常驻工位、记工笔数、总件数、废品数、应发计件总工资、已结算笔数。
3. **【工位车间产量汇总表】导出**：包含工位代码、工位名称、所属部门与车间、责任人、合格总产出、废品总数、工费总支出、流水笔数。
